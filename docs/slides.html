Problem Modeling

Vehicle Routing Problem with Time Windows (VRPTW)

NCKH

Mathematical Foundations

  • Objective Context: Dispatch a homogeneous fleet of vehicle capacity \(Q\) to serve a set of customer demands \(q_i\) at locations \(\mathcal{N}\).
  • Hard Operations Constraints:
    • Capacity limits: Sum of demands along any route \(\le Q\).
    • Time Windows: Arrival at customer \(i\) must occur within \([e_i, l_i]\). Early arrival induces waiting; late arrival is strictly infeasible.
  • Lexicographical Objective Hierarchy:
    $$\operatorname{lex}\;\min \left( \text{Fleet Size } (NV), \;\; \text{Travel Distance } (TD) \right)$$

Motivation

Research Motivation & Operational Gaps

NCKH

Fleet Economics & Logistics Objectives

  • Fleet Costs Dominate: In actual fleet operations, adding a single vehicle incurs fixed labor, capital overhead, and licensing costs equivalent to 10× to 50× the variable fuel cost of marginal travel distance changes.
  • Lexicographical Entrapment: Solvers frequently trade off vehicle count (increasing fleet size) to yield a slightly lower total travel distance. This leads to artificial "fleet inflation".
  • Actionable Tooling Needs: Dispatch operators require not only raw heuristic solutions but interactive, low-latency Gantt diagrams and map rendering to manage live deliveries.

⚠ The "Fleet Inflation" Trap

Traditional metaheuristics optimize scalar values: \(Cost = \alpha \cdot NV + \beta \cdot TD\). If \(\alpha\) is set too low, the algorithm sacrifices vehicle bounds to optimize travel coordinates.

Methodology

Hierarchical MDP Solver Core

NCKH

Dual-Level Decision Process

  • Macro-Level (Plateau Controller):
    • Monitors solver convergence. Triggers if search stagnates for \(60\) iterations.
    • Observes state \(s_t^c \in \mathbb{R}^{12}\); selects target mode \(m_t \in \{ \text{Intensify, Diversify, TW-Rescue, Recombine, Reduce} \}\).
  • Micro-Level (Operator Controller):
    • Triggers at every search step. Observes state \(s_t^o \in \mathbb{R}^{15}\).
    • Selects destroy-repair operator pair \(a_t \in \{0, \dots, 54\}\).
  • Thompson Bandit Integration: Dynamically balances and updates operator likelihoods dynamically based on real-time success feedback.

Methodology

Set Partitioning Route Recombination

NCKH

Neural Acceptance & Hybrid Optimization

  • Learned Acceptance Criterion (LAC):
    • Replaces traditional, static Simulated Annealing (SA).
    • Classifier network trained via online hindsight labels: predicts whether accepting a degraded search move is likely to lead to downstream improvements within horizon \(H = 80\).
  • Set Partitioning Route Recombination:
    • Extracted routes from a dual-retention pool are solved periodically:
      $$\min \sum_{j \in R_{\text{pool}}} (P_{\text{vehicle}} + c_j) y_j \quad \text{s.t. } \sum_{j \in R_{\text{pool}}} a_{ij} y_j = 1, \;\; y_j \in \{0, 1\}$$
    • Solved via SciPy MILP under a strict \(4.0\text{s}\) limit, scaling \(P_{\text{vehicle}} \in \{10, \dots, 50\}\).

Dual-Retention Route Pool

1. Elite Route Memory

Caches disjoint routes from the top-scoring solutions found throughout the run, preserving high-quality sub-routes.

2. Diversity Route Cache

Tracks distinct routes that utilize alternative links to guarantee routing variety during optimization.

★ Scalability Priority: Limits MILP problem size to 500 decision variables.
Methodology

Proactive Pool Seeding & Route Generation

NCKH

Overcoming Feasibility Entrapment

  • The Challenge: Traditional local search generates routes reactively. Difficult instances (e.g. Solomon RC101) require highly complex "bridge routes" to reduce vehicle count.
  • Proactive Seeding Mechanisms:
    1. Randomized Clarke-Wright Savings: Constructs temporal bridge routes between spatially distant but highly compatible nodes.
    2. NV-Targeted Construction: Forces greedy routing variants directly aiming for \(NV-1\) vehicle counts.
    3. Regret-3 Large Destroy (40-65%): Removes up to 65% of the graph, forcing extensive reorganizations to pack routes.

Methodology

Graph Neural Network Guided Search

NCKH

Dynamic Edge Optimization

  • Neural Heatmap Predictor: A lightweight Graph Neural Network predicts edge optimality probabilities \(P_{ij} \in [0, 1]\) exactly once during initialization.
  • GNN-Biased Heuristics: Re-scales detour insertion costs dynamically during regret/greedy heuristics:
    $$\text{detour}' = \text{detour} \times (1.0 - \gamma P_{iu})(1.0 - \gamma P_{uj})$$
    Where \(\gamma \in [0.1, 0.6]\) is scaled based on target mode.
  • Search Pruning Schedule: Linear threshold decay (\(\theta = 0.05 \to 0.003\)) eliminates unlikely edge transitions, pruning the search space to accelerate large instances.

Methodology

Post-Processing Search Polish Cascade

NCKH

Cascade Optimization Pipeline

  • Depth-3 Ejection Chains: Attempts to empty sparsely-populated routes by displacing customers up to 3 levels deep:
    \(c \rightarrow R_i \text (ejects } d) \rightarrow d \rightarrow R_j \text (ejects } e) \rightarrow e \rightarrow R_k\)
  • Buffered Route Elimination: Triggers multi-route spatial rebalancing if \(NV = NV_{\text{BKS}} + 1\) to force target vehicle termination.
  • Committed NV Search: Locks the solution to \(NV-1\) vehicles and executes a strict \(1500\)-iteration SA pathing search with pool-based restarts.
  • Convergent TD Polish: Executes 2-opt and Or-opt (\(1, 2, 3\)) steps along all active routes until distance convergence bounds (\(\Delta c < 10^{-9}\)).

The Fallacy of Raw Travel Distance Gaps

  • Distorted Comparisons: Travel Distance (TD) comparisons are mathematically flawed if vehicle counts are not matched. Extra vehicle capacity relaxes spatial routing limits, artificially lowering travel distance.
  • Strict Fair Intersection Protocol (\(N=39\)):
    • Isolates the subset of 39 Solomon instances where both solvers successfully matched BKS vehicle counts.
    • Guarantees a mathematically direct comparison of routing efficiency under identical time constraints.

Evaluation

Homberger Scalability & Computational Overhead

NCKH

Large-Scale Routing Profiles

  • 200-Customer Scale (Robust Performance):
    • Both solvers converge to identical vehicle limits.
    • Hybrid-DDQN limits vehicle degradation rates to **0% - 20%** compared to **30% - 70%** for ALNS-Base.
  • 400-Customer Scale (Suboptimal Degradation):
    • Neither solver approaches the BKS limits (e.g. BKS NV=4 on R2_4_1, solvers land at 8.10 - 8.80).
    • However, Hybrid DDQN-ALNS yields a statistically significant edge of 0.70-0.80 vehicles (Wilcoxon \(p=0.0156\) on R2_4_1).

Computational Performance Limits

Computational Overhead

The hybrid solver is a quality-maximizing strategy that trades CPU cycles for routing accuracy.

• Solomon-100: 1.5x - 4.0x slower runtime.
• Homberger-200: 1.3x - 4.6x slower runtime.
• Homberger-400: Up to 100x slower on pathological configurations due to large dense MILP matrices.

Q&A Preparation

Defense Strategy Panel (Q&A Guidelines)

NCKH

Pre-empting Academic Review Committee Objections

Q1: Why is the hybrid solver execution runtime slower than standard ALNS?

Answer: It represents a deliberate, cost-minimizing trade-off. For logistics companies, saving a single vehicle reduces fixed monthly overheads (capital depreciation, licensing, driver salaries) by thousands of dollars. Investing an extra 2-3 minutes of server computation before vehicles dispatch yields substantial cost reductions compared to starting immediately with an extra truck.

Q2: Why do you report GNN performance checks on only 3 instances (C101, R101, RC101)?

Answer: The GNN evaluations in Section IV-F serve as a representative case study to verify that neural heatmaps properly adjust to distinct spatial configurations (clustered, random, mixed). Due to deep execution costs, we focused on trace convergence profiling. Complete results showing average metrics across all 56 instances are reported in our main thesis paper.

Q3: How do we know these solver improvements are mathematically significant and not random?

Answer: All comparative distance assertions are validated using the non-parametric Wilcoxon Signed-Rank Test at a strict significance boundary (\(\alpha = 0.05\)). The improvements are accompanied by explicit statistical validation (e.g. \(p = 0.0078\) on instance c2_4_1), proving the hybrid solver benefits are mathematically significant.
